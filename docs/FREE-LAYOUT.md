# 자유 분할 및 9칸 지원

## 사용 방법

1. 모니터를 고른 다음 **자유 분할**을 선택한다.
2. **세로로 자르기** 또는 **가로로 자르기**를 누르고, 미리 보기에서 자를 위치를 클릭한다. 전체 화면 또는 기존의 한 칸만 나뉜다.
3. 경계선을 끌어 위치를 조절한다. 경계의 다른 쪽 칸은 자동으로 채워지며 하위 분할은 유지된다.
4. 마지막 작업은 **마지막 자르기 취소**로 되돌리고, **분할 초기화**는 자르기 전 한 화면으로 되돌린다.
5. 최대 9칸까지 만들 수 있다. 균등한 9칸은 **격자 9분할**을 선택한다. 자유 분할의 픽셀 크기는 자른 결과로 계산되므로 크기 입력란은 읽기 전용이다.
6. 실제 화면 변경은 **분할 적용**을 눌렀을 때만 실행된다. 편집·경계선 이동·초기화는 화면 설정을 변경하거나 사용자 설정 파일을 저장하지 않는다. 적용에 성공하면 자유 분할의 자르기 정보도 저장하며, 거절·실패 복원용 스냅샷에 포함한다.

설정 편집 화면을 메인에 항상 표시한다. 원본 화면으로 복원하거나 상태를 갱신해도 편집 화면을 숨기지 않는다. 별도의 현재 상태 미리 보기와 칸 목록을 제거했다. 실제 상태 조회와 작업 버튼 갱신은 유지한다.

선택 칸과 기억할 창도 9개까지 처리한다. 단축키도 1~9번까지 지원하며, 공통 보조키는 Ctrl+Alt+Shift다. 숫자 1~9는 현재 화면의 배치 위치 변경, F1~F9는 선택 칸 지정, F10은 앱 열기, F11은 분할 적용, 숫자 0은 원본 복원이다. F12는 Windows 예약 키라 사용하지 않는다. 키 조합은 설정에서 바꿀 수 있다.

이전 기본 단축키만 새 기본값으로 옮긴다. 사용자 지정 조합과 개별 사용 해제는 보존한다. 새 기본값이 사용자 지정 조합과 겹치면 해당 기본 동작만 사용 해제해 기존 조합을 보호하고, 설정에서 다시 지정할 수 있게 한다. 없는 칸을 요청하면 화면을 변경하지 않고 안내한다.

## 호환성 및 통신

- Windows 10 21H2/Windows 11 x64, .NET 10/C++20.
- 드라이버 프로토콜 v3: 최대 9개, DESKSPLIT_CONFIG 944바이트. 상태 8바이트와 선택적 어댑터 진단 12바이트는 유지한다. 이전 드라이버에는 큰 설정을 보내지 않으며 일치하는 드라이버를 설치해야 한다.
- 실시간 배치 메시지 v2: 64비트 값에 9개의 4비트 화면 번호, 4비트 개수, 프로토콜 서명을 넣는다. 교환은 WPARAM/LPARAM으로 새 값/예상 값을 전달하며 포인터를 사용하지 않는다. 기존 합성기 메시지와 구분한다.
- 임의의 최소 640픽셀 제한은 없으며, 양수 영역과 D3D11의 실제 텍스처 한도는 유지한다.
- 드라이버의 어댑터 초기화가 완료되기 전에는 앱과 드라이버 모두 새 분할 요청을 거절한다. 요청을 보관했다가 나중에 자동 적용하지 않는다. VM 검사도 준비 완료를 확인한 뒤에만 SET을 보내며, 검사 제한 시간은 제품 동작 타이머와 별개다.
- UMDF 설정은 서비스 전용 레지스트리 하위 키에 읽기/쓰기 권한을 명시해 저장한다.

## 검증 기록

- .NET 빌드 경고 0/오류 0, C++20 합성기·WDK 드라이버 빌드 성공.
- 900개의 9칸 기하 사례(빈틈·겹침·경계·홀수 해상도), 300개의 9칸 라우팅 순열 통과.
- 9개 창 합치기·재분할과 9번 선택 칸 전경 순서, 자유 분할 저장/복원·드래그·취소·초기화·원본 복원 후 편집 표시를 가짜 어댑터와 오프스크린 UI로 검사했다.
- 네이티브 기하/라우팅 87개, 드라이버 해상도·EDID 90개 검사 통과.
- 새 설치 파일에 앱·합성기·개발 서명 드라이버를 함께 담았다. 임베디드 10개 파일의 SHA256 및 INF·배포 의존성 검사가 통과했다.
- Windows 10 21H2(19044.1288, Enterprise LTSC)에서 초기 패키지는 어댑터 상태 1 / STATUS_PENDING(0x103)에 머물렀다. 같은 DLL에 INF 버전만 달리한 대조 검사에서 `23.24.9.1`은 대기, `0.38.43.63`은 상태 2 / 성공으로 달라졌다. 정확한 OS 내부 원인은 아직 확정하지 않았다.
- 실제 프로토콜 v3 드라이버도 INF `0.38.43.65` 패키지로 준비 완료되었으며, 4개 생성 → 해제 → 9개(각 640×360) 생성 → 해제에 성공했다. 설치·재설치와 관리 코드/UI 검사를 포함해 27단계가 통과했다. 기록: `artifacts/nine-version-fix-validation/summary.json`, `fhd-roundtrip.json`. 이 검사는 드라이버 모니터 수를 확인하며, Windows의 활성 데스크톱 배치나 실제 합성 화면을 입증하지 않는다.
- 정식 빌드는 WDK 기본 시간 기반 버전 대신 제품 버전 `0.5.6.0`을 명시한다. 예전 드라이버가 버전 순위 때문에 남지 않도록 설치 시 동봉 패키지를 일치하는 장치에 명시적으로 연결한다. 이 최종 설치 파일의 VM 설치·기존 버전 업그레이드는 아직 검증하지 못했다.
- 사용자가 현재 사용 중이라고 확인한 두 VM은 보호 대상으로 기록하고 검사 대상에서 제외했다. 별도 VM의 OS 디스크와 1920×1080 → 활성 3×3 배치 → 9색 합성 → 원본 복원 검사 도구를 준비했다. 호스트 여유 메모리가 2GB VM과 4GB 예비 메모리 기준에 미달해 새 VM 시작 전에 중단했다. **활성 9칸 및 합성 화면 검증은 미완료**다.
- 호스트에는 새 드라이버를 설치하지 않았고, 디스플레이 설정과 실제 창 위치는 변경하지 않았다. 이전 프로토콜 v2의 성공 기록은 이번 v3/9칸의 성공 근거로 사용하지 않는다.

최종 검증 대기 설치 파일: `artifacts/installer/DesktopSplitter-0.5.6-FreeLayout9-win-x64-Setup.exe`. SHA256: `C2E1DBBAC29D09DB65A257E96D223D299194EC9A9616CD1943B9FD95EC2AD370`. 실사용 검증을 완료한 배포본으로 확정하지 않았다. 임베디드 10개 파일의 SHA256 검사는 통과했다.

검사 보완: 위 성공 기록에서 설치 로그와 배포 DLL SHA256은 v3 패키지를 가리키지만, `Win32_PnPSignedDriver` 버전은 이전 `0.38.43.63`으로 표시됐다. 다음 검사는 WMI 값에 의존하지 않고 `DEVPKEY_Device_DriverVersion` 및 `DEVPKEY_Device_DriverInfPath`도 조회해 선택한 제품 버전과 실제 장치 연결이 일치하는지 필수 확인한다. 이전 기록의 버전 표시는 최종 업그레이드 검증을 대신하지 않는다.

## 2026-10-22 안정화

- 낮은 해상도로 모니터를 바꿨을 때 중첩된 자르기가 0픽셀을 만들면, 편집기 예외 대신 해당 초안의 적용을 막고 자르기 취소·초기화를 제공한다. 자르기 이력은 남긴다. 임의의 최소 크기는 추가하지 않았다.
- 모니터·분할 방식을 바꾸면 이전 경계선 드래그를 해제한다. 자유 분할 자체의 연속 드래그는 유지한다.
- 잘못되거나 중복된 단축키만 사용 해제하며, 다른 사용자 지정 키와 전체 사용 상태는 보존한다. 설정은 저장 전까지 디스크에 쓰지 않는다.
- 분할 적용 전의 번호 순서를 복원 스냅샷에 포함한다. 적용 거절·실패 시 이전 모양을 재생성한 다음 검증된 번호 순서를 복원하고, 이후 기억한 창을 복원한다. 원래 순서라면 추가 배치 요청을 보내지 않는다.
- 복원 대상은 저장한 모니터 장치 경로로 확인한다. Windows 디스플레이 이름이 재사용된 다른 모니터에 복원하지 않는다. 장치 경로가 없던 구버전 기록만 기존 이름 조회를 사용한다.
- 칸 수 불일치·중복 장치가 있는 화면 연결 정보는 번호 매핑 전에 거절한다.

회귀 검사는 가짜 디스플레이·창 어댑터 및 오프스크린 UI에서 수행했다. 9칸→4칸 전환, 5~9번 단축키, 없는 칸 입력, 중첩 자르기의 해상도 변경·복구, 번호 순서 복원과 잘못된 복원 기록을 포함한다. 실제 모니터 배치·창 위치를 변경하거나 드라이버를 설치하지 않았다. 실제 9칸 합성 출력과 새 설치 파일의 Windows 10 VM 설치·업그레이드는 여전히 별도 검증이 필요하다.

### 추가 안정화 검사

- 잘못된 키 조합이 편집 중이어도 전역 단축키 전체 끄기와 저장은 허용한다. 다시 켤 때는 활성 항목의 유효성을 검사한다.
- 네이티브 단축키 해제가 실패하면 남은 등록을 기록해 재시도하되, 즉시 메시지 실행을 막는다. 편집 중이거나 끈 것으로 의도한 키가 디스플레이 동작을 실행하지 않게 한다.
- 드라이버의 화면 개수만으로 선택 칸 UI를 활성화하지 않는다. 실제 연결 목록의 개수·번호·장치 중복과 조회 오류를 함께 검사한다. 연결이 불명확하면 선택 목록과 선택 배지를 해제하고 안내하며, 정상 조회 후 다시 활성화한다. 표시용 로그 행 개수는 선택 가능 번호 판단에 사용하지 않는다.

실패 재현 검사(가짜 등록기의 해제 실패, 연결 목록 조회 실패)를 수정 전에 실행해 실패를 확인했고 수정 후 통과했다. 잘못된 키 편집 중 전체 끄기, 중복 장치 조회, 정상 조회로의 복구도 추가했다. 작업 표시줄에 따른 창 좌표 혼용 의심은 기존 `SplitWindowMover.Plan`에서 이미 작업 영역 보정을 하는 것을 확인해 오류로 확정하지 않았으며 해당 계산은 바꾸지 않았다.

### 다중 모니터 이동 및 숨은 창 수정

가려진 원본 모니터를 단순히 마우스 금지 영역으로 처리하면 다른 물리 모니터로 가는 경로가 끊길 수 있었다. 새 경계 계산은 원본 물리 모니터의 실제 좌우·상하 이웃과 표시 칸→캡처 원본의 번호 매핑을 함께 사용한다. 번호 교환과 기본 모니터 변경으로 좌표가 음수가 되는 경우에도 새 스냅샷을 사용한다. 직사각형 ClipCursor는 사용하지 않으며, 불완전한 연결 상태나 실패한 마우스 좌표 변경 때문에 입력을 삼키지 않는다. 가상 캡처 데스크톱이 다른 물리 모니터와 겹치면 전체 캡처 그룹만 비어 있는 영역으로 옮긴다. 다른 물리 모니터의 상대 배치는 유지한다.

기존 창이 합성 창 아래에 남은 채 작업 표시줄에서 다시 선택됐을 때 FOREGROUND 이벤트를 처리하도록 보완했다. 시작 시 이미 가려진 창도 확인하며, 완전히 화면 밖에 있는 창은 사용자가 활성화한 경우에만 복구를 요청한다. 정상 창의 복구 영역은 한 칸이 아닌 전체 분할 그룹이다. 여러 칸에 걸치는 일반 창의 크기를 한 칸에 맞춰 강제로 줄이지 않는다. 최대화는 Windows의 개별 모니터 동작을 유지한다. 배치는 비동기 요청이며, 다른 물리 모니터에서 보이는 창·최소화 창·클로킹된 창·셸/도구 창은 옮기지 않는다.

검증: 순수 네이티브 계산 287개 및 관리 코드/UI 회귀 검사 10개 통과. 4·9칸, 역순 번호 교환, 사방 이웃, 음수 좌표, 높이가 어긋난 이웃, 1픽셀 영역, 바뀐 해상도, 전체 분할을 가로지르는 1600×900 창의 배치를 포함한다. 실제 마우스/창 이동과 다중 물리 모니터에서의 합성 출력은 이 PC에서 실행하지 않았다. 수정 설치 파일을 설치하고 사용자가 직접 분할을 다시 적용해 확인해야 하는 상태다.
